# SkyrimNet Triggers, Actions & Memory/Profile Generation Audit Report

---

## 1. Triggers & Events Audit: Why `direct_narration` Fires for Non-Nearby Actors

### Root Causes in the Event Pipeline

1. **Every Trigger YAML Uses `direct_narration` Only Conditioned on `skipTrigger == false`**
   - All 25 YAML files in [`SKSE/Plugins/SkyrimNet/external/tetherball88.maras/triggers/`](../SKSE/Plugins/SkyrimNet/external/tetherball88.maras/triggers) configure `response.type: "direct_narration"` (24 with `audience: "nearby_npcs"`, 1 with `audience: "triggering_actor"`), and their `eventCriteria` only check `skipTrigger == false`.
   - Whenever `SkyrimNetApi.RegisterEvent("ttm_event", json, speaker, target)` is called with `"skipTrigger": false`, SkyrimNet immediately attempts to fire `direct_narration` for the event—even if one or both actors are unloaded, in another city, or if the event was generated by a background timer or UI action.

2. **Zero Proximity Gating in [`TTM_ServiceSkyrimNet.psc`](../Scripts/Source/TTM_ServiceSkyrimNet.psc) and C++ Event JSON Builders**
   - [`BuildJson`](../Scripts/Source/TTM_ServiceSkyrimNet.psc#L914-L928) defaults to `bool skipTrigger = false`, and [`BuildPregnancyAnnouncedJson`](../SKSE_Source/src/core/SkyrimNetIntegration.cpp#L2547-L2597) / [`BuildChildBirthJson`](../SKSE_Source/src/core/SkyrimNetIntegration.cpp#L2599-L2653) hardcode `j["skipTrigger"] = false`.
   - None of the `Register*` functions in [`TTM_ServiceSkyrimNet.psc`](../Scripts/Source/TTM_ServiceSkyrimNet.psc) check whether `speaker` (and `target`, when applicable) are 3D-loaded and within `skyrimnetActionRadius` of the Player before setting `skipTrigger = false`.

3. **Player Fallback When `speaker == None` Guarantees False Local Narration**
   - In [`RegisterChildBirth`](../Scripts/Source/TTM_ServiceSkyrimNet.psc#L349-L353), [`RegisterChildGrewUp`](../Scripts/Source/TTM_ServiceSkyrimNet.psc#L407-L411), [`RegisterChildSentToTraining`](../Scripts/Source/TTM_ServiceSkyrimNet.psc#L474-L478), [`RegisterChildBecameAdult`](../Scripts/Source/TTM_ServiceSkyrimNet.psc#L537-L541), and [`RegisterPaternitySecretEvent`](../Scripts/Source/TTM_ServiceSkyrimNet.psc#L709-L718), when the NPC parent is unloaded (`speaker == None`), the script falls back to:
     ```papyrus
     if(speaker == none)
         speaker = TTM_Data.GetPlayer()
     endif
     SkyrimNetApi.RegisterEvent("ttm_event", json, speaker, none)
     ```
   - Because `speaker` becomes the **Player** and `skipTrigger` is `false`, SkyrimNet treats the off-screen event as happening at the Player's exact location and forces nearby random NPCs around the player to react via `direct_narration`.

### Recommended Fixes for Part 1
1. **Centralize Proximity Gating for `skipTrigger`**:
   - Add a helper in C++ / Papyrus (e.g., `MARAS.ShouldTriggerSkyrimNetNarration(Actor speaker, Actor target = None)`) that returns `true` **only** when:
     - `speaker != None` and `speaker.Is3DLoaded()` and is in the Player's current cell / within `skyrimnetActionRadius`, **AND**
     - If `target != None`, `target.Is3DLoaded()` and is also within `skyrimnetActionRadius` of the Player (and `speaker`).
   - Pass `skipTrigger = !MARAS.ShouldTriggerSkyrimNetNarration(speaker, target)` into `BuildJson` / `BuildPregnancyAnnouncedJson` / `BuildChildBirthJson`.
2. **Never Fall Back to `speaker = Player` with `skipTrigger = false`**:
   - When `speaker == None` (unloaded NPC), either skip `RegisterEvent` entirely (and record a permanent memory instead—see Section 3) or force `skipTrigger = true`.
3. **Suppress `ttm_event` Registration During Background Matchmaking**:
   - When [`MatchmakingService::ApplyMatch`](../SKSE_Source/src/core/MatchmakingService.cpp#L4471) mutates state, it is a background/world-state transition (not a live scene happening in front of the player). Either pass a `silent/background` flag or set `skipTrigger = true` so background matchmaking never triggers `direct_narration`.
4. **Deduplicate Two-Parent Child Event Calls**:
   - In [`RegisterChildAdopted`](../Scripts/Source/TTM_ServiceSkyrimNet.psc#L199-L202), [`RegisterChildInherited`](../Scripts/Source/TTM_ServiceSkyrimNet.psc#L220-L223), and [`RegisterChildParentsChanged`](../Scripts/Source/TTM_ServiceSkyrimNet.psc#L247-L250), when registering for the second parent (`parentB` / `coParent`), always pass `skipTrigger = true` on the second call so the trigger does not fire twice.

## 3. Memories (LLM-Generated) vs. Profile Updates (Placed Child / Adult Spawn Only)

### How M.A.R.A.S & SkyrimNet Handle Memories vs. Profiles
- **Unified Multi-Participant Episode Memory Service ([`SkyrimNetMemoryService`](../SKSE_Source/include/core/SkyrimNetMemoryService.h) $\rightarrow$ [`maras_event_memories.prompt`](../SKSE/Plugins/SkyrimNet/external/tetherball88.maras/prompts/maras_evaluations/maras_event_memories.prompt) $\rightarrow$ `AddActorMemory` / `PublicAddMemory`)**:
  - Rather than building dry, formulaic strings from raw facts or firing separate LLM calls on every back-to-back state change, all relationship, infidelity, paternity, child birth, adoption, inheritance, and matchmaking memory generation is unified in [`SkyrimNetMemoryService`](../SKSE_Source/src/core/SkyrimNetMemoryService.cpp).
  - **90-Second Connected-Participant Episode Buffer (`MemoryEpisode`)**: Incoming events within a 90-second grace window that share participants are merged into a single chronological `MemoryEpisode` timeline and flushed in **one single LLM call** (`maras_event_memories.prompt`), producing one combined, mutually consistent first-person memory per target NPC.
  - **Single-Request Shared Scene + Per-NPC Knowledge Restrictions (Zero Secret Bleed)**: Connected events and participants stay in the same `MemoryEpisode` and single LLM prompt so shared scenes remain mutually consistent across all participants, while each target NPC in `maras_event_memories.prompt` has explicit `knowledgeRestrictions` (`What <Name> DOES NOT Know`) instructing the LLM on what secrets or unwitnessed events that NPC is unaware of and must never bleed into their memory or tags.
  - **No Pre-Computed Reason Strings**: Canned `result.memory` strings are never passed into the memory prompt; the LLM crafts character-voiced memories from the character profiles and the chronological episode timeline.
- **Character Profile Updates (`character_bio`)**:
  - SkyrimNet profile generation/updates **only work on placed `Actor` references** in the game world (actors with a valid `RE::Actor*` / `ActorUUID`), **never on synthetic child records** (`0xFE000001+`).
  - Therefore, profile updates **cannot** be called on synthetic-only transitions such as `OnChildGrewUp` (FMR Newborn $\rightarrow$ synthetic Stage 2) or `OnChildFinishedTraining` (FMR synthetic Stage 3 $\rightarrow$ synthetic Stage 4), and are **not needed** for household relocations (which are already handled dynamically via `0602_maras_relations.prompt`).
  - Profile updates are needed **exclusively when a physical Young Child Actor (`Stage 2`) or Adult Child Actor (`Stage 4`) is spawned/placed in the world**.

---

### A. Where to Trigger LLM Memory Generation

1. **Relationship, Infidelity & Paternity Milestones**:
   - Use LLM memory generation (`SendCustomPromptToLLM` with `"memory"` variant $\rightarrow$ `AddActorMemory`) for major life events so the LLM can creatively craft character-flavored first-person memories from the characters' profiles and context after `ttm_event` scrolls out of `recent_events`:
     - **Live Relationship Transitions (Proposals, Marriage, Engagement, Breakups/Divorce, Open/Close Relationship)**: Generate first-person LLM memories for NPCs when status changes occur outside of background matchmaking (e.g., player/dialogue-initiated transitions).
     - **Infidelity Caught, Affair Confession, Exposure & Resolution**: Generate LLM memories for the cheater, victim, and/or paramour capturing how the betrayal was discovered or resolved.
     - **Paternity Secret Revealed / Discovered**: Generate LLM memories for the Mother, Presumed Father, and/or Biological Father when a pregnancy or paternity secret is confessed or discovered.
     - **Child Birth, Adoption & Inheritance**: Generate LLM memories for the parents/guardians when a child is born, adopted, or inherited following a parent's death.

---

### B. Where to Trigger Profile Generation / Updates (Strictly on Placed Child / Adult Actor Spawns)

Because profile updates only work on placed `Actor` references (not synthetic child IDs), trigger profile generation/update **only** at the two physical actor spawn points:

1. **Young Child Actor Spawned (`Stage 2` Placed `Actor`)**
   - **Exact Call Sites**:
     - [`TTM_ServiceChildrenLogic.SpawnSyntheticChild`](../Scripts/Source/TTM_ServiceChildrenLogic.psc#L1267-L1434) — when a synthetic Stage 2 child is physically spawned into the world via `PlaceAtMe` (`spawnedChild`).
     - [`TTM_ServiceFertilityFMR.OnChildSpawned`](../Scripts/Source/TTM_ServiceFertilityFMR.psc#L320-L380) — when FMR spawns a physical child `Actor` (`child`) and re-keys the synthetic child record via `MARAS.RegisterChildActor(..., stage = 2)`. *(Not in `OnChildGrewUp` / `OnChildGrewUpNpcNpc`, which are synthetic-only).*
     - [`TTM_ServiceFertilityBF.OnChildSpawned`](../Scripts/Source/TTM_ServiceFertilityBF.psc#L367-L414) — when Beeing Female spawns a physical child `Actor` (`childActor`) in the world.
